# v4 接口约定

网页和 FastAPI（Claude 写）通过下面两个函数调用 LangGraph（你写）。只要函数签名和产出格式不变，两边可以各自开发、互不影响。

```
浏览器 ──SSE──> app/api/routes.py ──调用──> app/agent/graph.py
         （Claude：把 chunk 翻译成网页能显示的事件）   （你：astream / aresume）
```

## 你要在 `app/agent/graph.py` 里实现的

```python
async def astream(url: str, question: str | None, thread_id: str):
    """第一次运行。原样 yield graph.astream(..., stream_mode='updates') 的每个 chunk。"""

async def aresume(thread_id: str, approve: bool):
    """中断后继续。原样 yield graph.astream(Command(resume=approve), ..., stream_mode='updates') 的每个 chunk。"""
```

### 产出格式：直接用 LangGraph 原生的 chunk，不用自己转换

`stream_mode='updates'` 时，每执行完一个节点，LangGraph 会给出一个 chunk：

```python
{'blame': {'blame_lines': [...], 'new_shas': [...], 'depth': 0}}   # 节点名 -> 这个节点返回的 dict
```

触发 `interrupt(value)` 时，chunk 是：

```python
{'__interrupt__': (Interrupt(value={...}, id='...'),)}
```

你只管 `yield chunk`，**不要**转 JSON、不要拼文字，翻译成网页事件是接口层的事。

### interrupt 的 value

```python
interrupt({'depth': 当前层数, 'missing': '还缺什么'})
```

- `depth`：int，网页上显示"已经挖到第几层"
- `missing`：str，网页上显示"还缺什么"，帮用户决定要不要继续

### resume 的值

`aresume(thread_id, approve)` 里的 `approve` 原样作为 `Command(resume=approve)` 传进去，`interrupt()` 的返回值就是它：

- `True`：用户选"继续深挖"，比如上限放宽一层，接着往前挖
- `False`：用户选"就到这里"，直接去 narrate，报告里注明是在哪一层停下的

具体怎么放宽、放宽几层，由你决定。

## 几个必须注意的点

1. **graph 只编译一次，放在模块级别。** 现在的 `run()` 每次调用都 `build_graph()`，如果 `astream` 也这样做，每次请求都会新建一个 `MemorySaver`。中断后 `aresume` 拿到的是另一个空的 checkpointer，找不到之前的状态。
2. **`thread_id` 由接口层生成**（uuid），你只负责把它放进 `config={'configurable': {'thread_id': thread_id}}`。同一个 `thread_id` 在 `astream` 和 `aresume` 里必须一致。
3. **节点里的 `asyncio.run()` 不用改。** 已经验证过：`graph.astream` 会把同步节点放到线程池里执行，那里没有正在运行的事件循环，`asyncio.run()` 能正常工作。路线文件里的"async 改造"可以跳过。
4. **`run()` 保留。** 同步接口 `POST /api/excavate` 还在用它。改成需要 checkpointer 之后，如果签名变了，告诉 Claude 改接口。

## 接口层会读取的字段

网页上每一步显示的摘要，来自这些节点返回值里的字段。字段改名或删掉不会报错，只是网页上那一步显示得更少；改了请同步一下：

| 节点 | 读取的字段 |
|---|---|
| parse_target | `owner` `repo` `file_path` `start_line` `end_line` |
| blame | `blame_lines`（每条的 `sha`） |
| filter_noise | `new_shas` `skipped`（每条的 `sha` `summary` `reason`） |
| link_context | `commits`（每条的 `sha` `date` `message`）、`issues`（每条的 `number` `title` `is_pr` `via_pr`） |
| assess | `enough` `missing` `stop_reason` |
| expand_history | `depth` `new_shas` |
| narrate | `report` |

## 接口层提供的 HTTP 接口

| 接口 | 作用 |
|---|---|
| `GET /api/excavate/stream?url=...&question=...` | SSE。调用 `astream`，事件依次为 `start`、`step`……，可能出现 `interrupt`，最后是 `report` 和 `done`；出错时是 `fail` |
| `GET /api/resume/stream?thread_id=...&approve=true` | SSE。调用 `aresume`，事件格式同上 |
| `POST /api/excavate` | 同步版，调用 `run()`，等全部跑完一次性返回 |
| `GET /api/samples` | 首页示例 |
| `GET /api/meta` | 当前是否为演示模式 |

## 两种运行模式

- **演示模式**：`.env` 里加 `FAKE_AGENT=true`。接口改用 `app/agent/fake_stream.py`，返回预先写好的假数据，不访问 git、GitHub 和 LLM。网页右上角会显示"演示模式"
- **真实模式**：默认。调用你在 `graph.py` 里写的 `astream` / `aresume`；还没写好时，网页会显示错误提示

`fake_stream.py` 产出的 chunk 格式和真实的完全一样，可以当作你实现时的参考。

启动：

```bash
python -m uvicorn app.main:app --reload
```
