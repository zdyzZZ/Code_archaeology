# ADR-0002：blame 必须"穿透"格式化提交

- 状态：已决定
- 日期：TODO

## 问题

`git blame` 给的是每行**最后一次**被修改的 commit。但真实仓库里到处是这种提交：

- 全项目跑一遍 formatter（black / prettier / gofmt）
- 批量改缩进、行尾、换行符
- 文件重命名或移动目录
- 批量 lint 修复

这些提交会把整个文件的 blame **全部覆盖**成自己。于是你 blame 一行业务逻辑，
拿到的是"chore: apply black formatting"——一句有效信息都没有。

## 决定

三层处理：

1. **blame 时就忽略空白与移动**：`git blame -w -C -C -M`
   - `-w` 忽略空白变化
   - `-C -C` 跨文件追踪代码移动（重复两次提高检测强度）
   - `-M` 检测同文件内的移动
2. **识别并跳过噪声提交**：拿到 commit 后检查它的 diff，
   若"去掉空白后无变化"或改动文件数超过阈值且每文件改动极小 → 判为格式化提交，
   继续往上一层 blame
3. **跨重命名追溯**：`git log --follow -- <path>`

## 代价

- 慢。`-C -C` 是重计算，大文件明显卡
- 需要缓存：同一 repo + commit 的 blame 结果落盘

## 待验证

阈值怎么定（改动文件数 / 单文件改动行数）需要拿真实仓库调。
先用启发式，evals 跑起来后再调。
