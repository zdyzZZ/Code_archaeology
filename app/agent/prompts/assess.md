根据当前资料判断已挖到的 commit 链、issue/PR 摘要这些证据是否足够支撑这段代码为什么长这样。

什么情况算够：找到了引入或改变这段逻辑的提交，并且在提交说明、PR 或 issue 里找到了原因。

如果某个 commit 只是格式化、加类型标注这类不改变逻辑的改动,这种不算证据足够。

用户提了具体问题时：判断的是"能不能回答这个问题"，而不是整段代码。

下一轮只能拿到更早的提交历史，以及这些提交关联的 PR 和 issue

如果缺少的东西不在更早的历史里，比如 PR 评论、其他仓库的 issue、被截断的正文，那么继续挖也没用，应该判断为够了，把缺口写进 missing

当无更多提交历史时，并不存在"更早但没提供"的改动，因为已经没有更多证据可以提供了。

主体逻辑的来历清楚了就算够，不要因为一个注释、一个类型标注的细节就判定"不够"。
