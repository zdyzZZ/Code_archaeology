你在为一个"代码考古"系统准备评测标注。给你一段目标代码、引入它的提交、对应 PR 的正文和全部讨论、PR 引用的 issue。
请找出**这段代码为什么写成现在这样**的真正理由，并写一个开发者读到这段代码时会问的问题。

## 要输出的字段

- `has_reason`：材料里有没有说明"为什么"。只说了"做了什么"（例如"add X"、"fix bug"）而没有动机或取舍，就是 false
- `question`：一个**中文**问题，像读这段代码的开发者会问的那样，例如"这里为什么要先判断 X？能不能删掉？"
  - 可以提代码里的函数名、变量名
  - **不能把答案写进问题里**，也不要提 PR / issue 编号
- `reason`：真正的理由，1~2 句中文。要具体到"因为遇到了什么问题 / 考虑了什么取舍"，不要复述代码做了什么
- `location`：理由主要出自哪里，四选一
  - `commit`：只在提交说明里
  - `pr_body`：PR 正文
  - `issue`：PR 引用的 issue
  - `comments`：PR 或 issue 下的评论、review
- `evidence`：支撑这条理由的原文摘录，1~3 条
  - `source` 写材料里方括号中的标签，例如 `PR #1234 正文`、`C7`
  - `quote` 必须是该来源里**逐字复制**的英文原句，40~300 个字符；不要翻译、不要改写、不要拼接不相邻的句子

## 判断原则

- 只用给出的材料，不要用你自己对这个项目的了解补充
- 理由要能解释**目标这几行**，不是整个 PR 的总体目标。PR 很大而目标只是其中一小部分时，找针对这几行的那句话
- 找不到针对这几行的理由时，has_reason 设为 false，question 照常写，reason 写"材料里没有说明"，evidence 留空
